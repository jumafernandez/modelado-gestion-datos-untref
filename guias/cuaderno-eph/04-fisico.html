4  Modelo físico

El modelo físico es el esquema lógico escrito para un motor concreto: tipos de datos de PostgreSQL, restricciones y sentencias CREATE TABLE. Es lo que vimos en la presentación C03.

4.1 Crear la base

Primero, una base vacía. En pgAdmin: clic derecho sobre Databases, Create, Database…, y nombre eph. O en SQL:

CREATE DATABASE eph;

Todo lo que sigue se ejecuta conectado a eph. En pgAdmin, abrí el Query Tool sobre esa base; en psql, \c eph.

4.2 Tipos de datos

Columnas Tipo Por qué
Códigos, anio, trimestre, nro_hogar, componente, sexo, edad smallint Enteros chicos: ocupan 2 bytes
pondera, pondih integer Un ponderador llega a 38.200 y smallint admite hasta 32.767
codusu char(29) Siempre tiene 29 caracteres
Nombres y descripciones varchar(n) Texto de largo variable
Ingresos numeric(14,2) Montos exactos, sin los redondeos de los tipos de punto flotante

No usamos serial: ese tipo genera identificadores subrogados, y acá los identificadores ya vienen dados por INDEC.

Elegir el tipo es elegir qué datos acepta la columna. Si pondera fuera smallint, la carga fallaría en el primer hogar con un ponderador grande, y está bien que falle: mejor un error que un dato truncado.

4.3 Restricciones

Además de las claves primarias y foráneas, cada tabla declara las reglas que conocemos del dominio:

  • NOT NULL donde el dato no puede faltar.
  • CHECK para los rangos: el trimestre va de 1 a 4, el sexo es 1 o 2, la edad y los ingresos no son negativos, el ponderador es positivo.
  • UNIQUE para lo que no se puede repetir aunque no sea clave, como el nombre de un aglomerado.

Con estas reglas la base rechaza datos imposibles en el momento de cargarlos, no meses después en un análisis.

4.4 Las tablas

Se crean en orden: una tabla con clave foránea necesita que exista antes la tabla a la que apunta. Como en C03, las restricciones de una sola columna van junto a la columna y las de varias columnas, como restricciones de tabla.

La geografía:

CREATE TABLE regiones (
    id      smallint     PRIMARY KEY,
    nombre  varchar(40)  NOT NULL UNIQUE
);

CREATE TABLE aglomerados (
    id         smallint     PRIMARY KEY,
    nombre     varchar(60)  NOT NULL UNIQUE,
    id_region  smallint     NOT NULL REFERENCES regiones (id)
);

CREATE TABLE viviendas (
    codusu         char(29)  PRIMARY KEY,
    id_aglomerado  smallint  NOT NULL REFERENCES aglomerados (id)
);

Los catálogos:

CREATE TABLE tenencias (
    id           smallint     PRIMARY KEY,
    descripcion  varchar(60)  NOT NULL
);

CREATE TABLE parentescos (
    id           smallint     PRIMARY KEY,
    descripcion  varchar(40)  NOT NULL
);

CREATE TABLE niveles_educativos (
    id           smallint     PRIMARY KEY,
    descripcion  varchar(60)  NOT NULL,
    orden        smallint     NOT NULL UNIQUE
);

CREATE TABLE condiciones_actividad (
    id           smallint     PRIMARY KEY,
    descripcion  varchar(60)  NOT NULL
);

Los hogares, entidad débil: la clave primaria tiene cuatro columnas y se declara como restricción de tabla. La primera columna es, además, clave foránea hacia viviendas. La restricción del trimestre lleva nombre, para que el mensaje de error sea claro si alguna vez se viola.

CREATE TABLE hogares (
    codusu                  char(29)       NOT NULL REFERENCES viviendas (codusu),
    anio                    smallint       NOT NULL CHECK (anio >= 2003),
    trimestre               smallint       NOT NULL,
    nro_hogar               smallint       NOT NULL,
    id_tenencia             smallint       REFERENCES tenencias (id),
    ingreso_total_familiar  numeric(14,2)  CHECK (ingreso_total_familiar >= 0),
    pondera                 integer        NOT NULL CHECK (pondera > 0),
    pondih                  integer        NOT NULL CHECK (pondih >= 0),
    CONSTRAINT trimestre_valido CHECK (trimestre BETWEEN 1 AND 4),
    PRIMARY KEY (codusu, anio, trimestre, nro_hogar)
);

id_tenencia e ingreso_total_familiar aceptan NULL: hay hogares sin dato de tenencia y hogares que no respondieron sus ingresos. En el capítulo 5 vemos de dónde salen esos NULL.

Las personas heredan la clave completa del hogar. Como esa clave tiene cuatro columnas, la clave foránea también, y se escribe como restricción de tabla con FOREIGN KEY:

CREATE TABLE personas (
    codusu                       char(29)       NOT NULL,
    anio                         smallint       NOT NULL,
    trimestre                    smallint       NOT NULL,
    nro_hogar                    smallint       NOT NULL,
    componente                   smallint       NOT NULL,
    id_parentesco                smallint       NOT NULL REFERENCES parentescos (id),
    sexo                         smallint       NOT NULL CHECK (sexo IN (1, 2)),
    edad                         smallint       NOT NULL CHECK (edad >= 0),
    id_nivel_educativo           smallint       NOT NULL REFERENCES niveles_educativos (id),
    id_condicion_actividad       smallint       NOT NULL REFERENCES condiciones_actividad (id),
    ingreso_ocupacion_principal  numeric(14,2)  CHECK (ingreso_ocupacion_principal >= 0),
    ingreso_total_individual     numeric(14,2)  CHECK (ingreso_total_individual >= 0),
    PRIMARY KEY (codusu, anio, trimestre, nro_hogar, componente),
    FOREIGN KEY (codusu, anio, trimestre, nro_hogar)
        REFERENCES hogares (codusu, anio, trimestre, nro_hogar)
);

4.6 El diccionario de datos, dentro de la base

COMMENT guarda una descripción de cada tabla y columna en el catálogo de PostgreSQL. Anotamos el nombre original de cada variable en la EPH, así cualquiera puede volver a la documentación de INDEC.

COMMENT ON TABLE regiones    IS 'Regiones estadísticas de la EPH (variable REGION).';
COMMENT ON TABLE aglomerados IS 'Aglomerados urbanos relevados por la EPH (variable AGLOMERADO).';
COMMENT ON TABLE viviendas   IS 'Viviendas de la muestra. Una misma vivienda se visita en varios trimestres.';
COMMENT ON TABLE hogares     IS 'Hogares relevados en cada trimestre (base usu_hogar).';
COMMENT ON TABLE personas    IS 'Personas de cada hogar relevado (base usu_individual).';
COMMENT ON TABLE tenencias             IS 'Códigos de II7: régimen de tenencia de la vivienda.';
COMMENT ON TABLE parentescos           IS 'Códigos de CH03: relación de parentesco con el jefe/a del hogar.';
COMMENT ON TABLE niveles_educativos    IS 'Códigos de NIVEL_ED. La columna orden sirve para ordenar de menor a mayor nivel.';
COMMENT ON TABLE condiciones_actividad IS 'Códigos de ESTADO: condición de actividad.';

COMMENT ON COLUMN regiones.id                     IS 'REGION: código de la región.';
COMMENT ON COLUMN aglomerados.id                  IS 'AGLOMERADO: código del aglomerado.';
COMMENT ON COLUMN viviendas.codusu                IS 'CODUSU: código que identifica la vivienda y permite seguirla entre trimestres.';
COMMENT ON COLUMN viviendas.id_aglomerado         IS 'AGLOMERADO: aglomerado donde está la vivienda.';
COMMENT ON COLUMN hogares.anio                    IS 'ANO4: año del relevamiento.';
COMMENT ON COLUMN hogares.trimestre               IS 'TRIMESTRE: trimestre del relevamiento.';
COMMENT ON COLUMN hogares.nro_hogar               IS 'NRO_HOGAR: número de hogar dentro de la vivienda.';
COMMENT ON COLUMN hogares.id_tenencia             IS 'II7: régimen de tenencia. NULL si no hay dato.';
COMMENT ON COLUMN hogares.ingreso_total_familiar  IS 'ITF: ingreso total familiar, en pesos corrientes. NULL si el hogar no respondió ingresos.';
COMMENT ON COLUMN hogares.pondera                 IS 'PONDERA: ponderador del hogar (factor de expansión).';
COMMENT ON COLUMN hogares.pondih                  IS 'PONDIH: ponderador para los ingresos del hogar, corregido por no respuesta.';
COMMENT ON COLUMN personas.componente             IS 'COMPONENTE: número de orden de la persona dentro del hogar.';
COMMENT ON COLUMN personas.id_parentesco          IS 'CH03: parentesco con el jefe/a del hogar.';
COMMENT ON COLUMN personas.sexo                   IS 'CH04: sexo (1 = varón, 2 = mujer).';
COMMENT ON COLUMN personas.edad                   IS 'CH06: años cumplidos (0 = menos de un año).';
COMMENT ON COLUMN personas.id_nivel_educativo     IS 'NIVEL_ED: nivel educativo.';
COMMENT ON COLUMN personas.id_condicion_actividad IS 'ESTADO: condición de actividad.';
COMMENT ON COLUMN personas.ingreso_ocupacion_principal IS 'P21: ingreso de la ocupación principal, en pesos corrientes. NULL = no sabe o no responde.';
COMMENT ON COLUMN personas.ingreso_total_individual    IS 'P47T: ingreso total individual, en pesos corrientes. NULL = no sabe, no responde o sin dato.';

El diccionario se consulta con SQL, cruzando information_schema con la función col_description:

SELECT c.table_name  AS tabla,
       c.column_name AS columna,
       c.data_type   AS tipo,
       COL_DESCRIPTION(FORMAT('%I.%I', c.table_schema, c.table_name)::regclass,
                       c.ordinal_position) AS descripcion
FROM information_schema.columns c
WHERE c.table_schema = 'public'
  AND c.table_name = 'hogares'
ORDER BY c.ordinal_position;
8 filas
tabla columna tipo descripcion
hogares codusu character NA
hogares anio smallint ANO4: año del relevamiento.
hogares trimestre smallint TRIMESTRE: trimestre del relevamiento.
hogares nro_hogar smallint NRO_HOGAR: número de hogar dentro de la vivienda.
hogares id_tenencia smallint II7: régimen de tenencia. NULL si no hay dato.
hogares ingreso_total_familiar numeric ITF: ingreso total familiar, en pesos corrientes. NULL si el hogar no respondió ingresos.
hogares pondera integer PONDERA: ponderador del hogar (factor de expansión).
hogares pondih integer PONDIH: ponderador para los ingresos del hogar, corregido por no respuesta.

En pgAdmin los mismos comentarios aparecen en la pestaña Properties de cada tabla. En la unidad 5 volvemos sobre esta idea, la de los metadatos que viajan junto con los datos.
