Apéndice B. Cómo se generó este sitio

Este cuaderno es un libro de Quarto, un sistema que mezcla texto en Markdown con bloques de código y los convierte en un sitio web. Lo particular es que el código no se pega como ilustración: se ejecuta al generar el sitio y lo que ves debajo de cada consulta es lo que respondió PostgreSQL.

B.1 R como motor

Quarto delega la ejecución en un motor. Acá usamos knitr, el de R, que sabe ejecutar bloques SQL a través de una conexión DBI, la misma que usarían en un script de R. Cada capítulo empieza con un bloque oculto que abre la conexión:

library(DBI)

con <- dbConnect(
  RPostgreSQL::PostgreSQL(),
  dbname   = "eph",
  host     = "localhost",
  user     = "postgres",
  password = Sys.getenv("PGPASSWORD")
)

knitr::opts_chunk$set(connection = "con")

Con eso, un bloque SQL del documento fuente se escribe así:

```{sql}
SELECT nombre
FROM regiones
ORDER BY nombre;
```

knitr manda la consulta por la conexión y convierte el resultado en una tabla. Si al bloque se le agrega la opción output.var, el resultado queda en un data.frame de R en lugar de mostrarse; así se hizo el gráfico del ingreso per cápita.

Dos detalles técnicos:

  • knitr reconoce como sentencias sin resultado solo INSERT, UPDATE, DELETE, CREATE y DROP. Para COMMENT, REFRESH o ANALYZE hay un pequeño envoltorio que las ejecuta con dbExecute(). El mismo envoltorio escribe en castellano el pie de cada tabla.
  • \copy no es SQL sino un comando de psql, así que no puede viajar por DBI. En el capítulo 5 se ejecuta desde R llamando a psql con system2(), en un bloque oculto.

B.2 Los diagramas también son código

El DER está escrito en el lenguaje de Graphviz, que Quarto convierte en imagen al generar el sitio. Las cajas del esquema lógico son HTML con estilos propios, armadas como las de la presentación C02-3. Tener los diagramas como texto permite corregirlos como cualquier otro código y versionarlos junto con el resto del libro.

B.3 Para regenerarlo

Hace falta:

  • Quarto.
  • R con los paquetes DBI, RPostgreSQL, knitr y rmarkdown.
  • PostgreSQL con una base eph vacía, y psql disponible en la línea de comandos.
  • Los archivos hogares.csv y personas.csv del capítulo 5.

La contraseña de PostgreSQL y la carpeta de los CSV se pasan como variables de entorno, y después se genera el libro desde la carpeta del proyecto:

export PGPASSWORD="tu_contraseña"
export EPH_DATOS="/ruta/a/la/carpeta/eph"
quarto render

Los capítulos se ejecutan en orden: el 4 crea las tablas, el 5 las carga y el 6 las consulta. Todo el proceso tarda unos dos minutos y el resultado queda en la carpeta _book, un sitio estático que se puede abrir en el navegador o publicar, por ejemplo, en GitHub Pages.
