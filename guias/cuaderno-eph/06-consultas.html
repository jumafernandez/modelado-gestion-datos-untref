6  Consultas

La base está cargada. Ahora respondemos las preguntas del capítulo 1 con lo que vimos en la presentación C04: INNER JOIN, agregaciones, HAVING, IN, vistas y vistas materializadas. Sumamos una herramienta nueva, las expresiones de tabla comunes (WITH), que ordenan las consultas largas. Escribimos las consultas como en C04: un atributo debajo del otro, con alias cortos para las tablas.

6.1 Un hogar, con sus etiquetas

Empecemos por algo chico: el hogar de cuatro generaciones que vimos en el capítulo 1, ahora desde la base. Los códigos se traducen con un INNER JOIN a cada catálogo, y el sexo, que no tiene catálogo, con un CASE:

SELECT p.componente,
       pa.descripcion AS parentesco,
       CASE p.sexo WHEN 1 THEN 'Varón' ELSE 'Mujer' END AS sexo,
       p.edad,
       ne.descripcion AS nivel_educativo,
       ca.descripcion AS condicion_actividad
FROM personas p
INNER JOIN parentescos pa           ON p.id_parentesco = pa.id
INNER JOIN niveles_educativos ne    ON p.id_nivel_educativo = ne.id
INNER JOIN condiciones_actividad ca ON p.id_condicion_actividad = ca.id
WHERE p.codusu = 'TQRMNOSUTHKOTNCDEIJAH00902653'
  AND p.anio = 2026 AND p.trimestre = 1 AND p.nro_hogar = 1
ORDER BY p.componente;

6.2 ¿Cuántas personas representa la encuesta?

Contar filas da el tamaño de la muestra; sumar el ponderador estima la población. El ponderador está en el hogar, así que hace falta unir cada persona con su hogar por la clave completa:

SELECT h.anio,
       h.trimestre,
       COUNT(*) AS personas_encuestadas,
       SUM(h.pondera) AS poblacion_estimada
FROM personas p
INNER JOIN hogares h ON p.codusu = h.codusu AND p.anio = h.anio
                    AND p.trimestre = h.trimestre AND p.nro_hogar = h.nro_hogar
WHERE h.anio >= 2024
GROUP BY h.anio, h.trimestre
ORDER BY h.anio, h.trimestre;

Para llegar a la región hay que recorrer todo el modelo, de personas a regiones. Con UNION ALL agregamos una fila con el total:

SELECT r.nombre AS region,
       SUM(h.pondera) AS poblacion
FROM personas p
INNER JOIN hogares h     ON p.codusu = h.codusu AND p.anio = h.anio
                        AND p.trimestre = h.trimestre AND p.nro_hogar = h.nro_hogar
INNER JOIN viviendas v   ON h.codusu = v.codusu
INNER JOIN aglomerados a ON v.id_aglomerado = a.id
INNER JOIN regiones r    ON a.id_region = r.id
WHERE h.anio = 2026 AND h.trimestre = 1
GROUP BY r.nombre
UNION ALL
SELECT 'Total',
       SUM(h.pondera)
FROM personas p
INNER JOIN hogares h ON p.codusu = h.codusu AND p.anio = h.anio
                    AND p.trimestre = h.trimestre AND p.nro_hogar = h.nro_hogar
WHERE h.anio = 2026 AND h.trimestre = 1
ORDER BY poblacion;

6.3 Nivel educativo según el sexo

Queremos, para la población de 25 años o más, qué porcentaje de varones y qué porcentaje de mujeres alcanzó cada nivel. La consulta tiene pasos: armar el grupo de adultos, calcular los totales por sexo y dividir. Con WITH cada paso tiene nombre y se lee de arriba hacia abajo:

WITH adultos AS (
    SELECT p.sexo,
           ne.descripcion AS nivel,
           ne.orden,
           h.pondera
    FROM personas p
    INNER JOIN hogares h            ON p.codusu = h.codusu AND p.anio = h.anio
                                   AND p.trimestre = h.trimestre AND p.nro_hogar = h.nro_hogar
    INNER JOIN niveles_educativos ne ON p.id_nivel_educativo = ne.id
    WHERE h.anio = 2026 AND h.trimestre = 1 AND p.edad >= 25
),
totales AS (
    SELECT SUM(CASE WHEN sexo = 1 THEN pondera ELSE 0 END) AS varones,
           SUM(CASE WHEN sexo = 2 THEN pondera ELSE 0 END) AS mujeres
    FROM adultos
)
SELECT a.nivel,
       ROUND(100.0 * SUM(CASE WHEN a.sexo = 1 THEN a.pondera ELSE 0 END)
             / t.varones, 1) AS pct_varones,
       ROUND(100.0 * SUM(CASE WHEN a.sexo = 2 THEN a.pondera ELSE 0 END)
             / t.mujeres, 1) AS pct_mujeres
FROM adultos a
CROSS JOIN totales t
GROUP BY a.orden, a.nivel, t.varones, t.mujeres
ORDER BY a.orden;

6.4 Hogares que alquilan, 2018 y 2026

El porcentaje de hogares inquilinos por región, en el primer trimestre de cada año. IN filtra los dos años, y cada CASE dentro de SUM separa un año del otro. Los hogares sin dato de tenencia quedan afuera del cálculo:

SELECT r.nombre AS region,
       ROUND(100.0 * SUM(CASE WHEN h.anio = 2018 AND h.id_tenencia = 3 THEN h.pondera ELSE 0 END)
                   / SUM(CASE WHEN h.anio = 2018 THEN h.pondera ELSE 0 END), 1) AS pct_2018,
       ROUND(100.0 * SUM(CASE WHEN h.anio = 2026 AND h.id_tenencia = 3 THEN h.pondera ELSE 0 END)
                   / SUM(CASE WHEN h.anio = 2026 THEN h.pondera ELSE 0 END), 1) AS pct_2026
FROM hogares h
INNER JOIN viviendas v   ON h.codusu = v.codusu
INNER JOIN aglomerados a ON v.id_aglomerado = a.id
INNER JOIN regiones r    ON a.id_region = r.id
WHERE h.trimestre = 1
  AND h.anio IN (2018, 2026)
  AND h.id_tenencia IS NOT NULL
GROUP BY r.nombre
ORDER BY pct_2026 DESC;

6.5 Hogares con algún desocupado

Como dice C04, la mayor potencia de IN aparece con subconsultas. ¿Cuántas personas viven en un hogar donde hay al menos un desocupado? La subconsulta devuelve las claves de esos hogares e IN se queda con todas las personas que los integran:

SELECT COUNT(*) AS personas_encuestadas,
       SUM(h.pondera) AS poblacion
FROM personas p
INNER JOIN hogares h ON p.codusu = h.codusu AND p.anio = h.anio
                    AND p.trimestre = h.trimestre AND p.nro_hogar = h.nro_hogar
WHERE p.anio = 2026 AND p.trimestre = 1
  AND (p.codusu, p.anio, p.trimestre, p.nro_hogar) IN (
        SELECT codusu,
               anio,
               trimestre,
               nro_hogar
        FROM personas
        WHERE id_condicion_actividad = 2
          AND anio = 2026 AND trimestre = 1
      );
1 fila
personas_encuestadas poblacion
4914 4190977

Como la clave del hogar tiene cuatro columnas, IN compara las cuatro juntas, escritas entre paréntesis.

6.6 Tres generaciones bajo un mismo techo

¿En qué aglomerados es más frecuente que convivan tres generaciones o más? El parentesco con el jefe dice a qué generación pertenece cada persona: la madre, el padre o los suegros están una arriba; el jefe, su cónyuge y sus hermanos, en la misma; hijos, yernos y nueras, una abajo; los nietos, dos abajo. Un hogar tiene tres generaciones si sus integrantes cubren al menos tres de esos niveles.

WITH generaciones AS (
    SELECT codusu,
           anio,
           trimestre,
           nro_hogar,
           COUNT(DISTINCT CASE WHEN id_parentesco IN (6, 7)    THEN  1
                               WHEN id_parentesco IN (1, 2, 8) THEN  0
                               WHEN id_parentesco IN (3, 4)    THEN -1
                               WHEN id_parentesco = 5          THEN -2
                          END) AS cantidad
    FROM personas
    WHERE anio = 2026 AND trimestre = 1
    GROUP BY codusu, anio, trimestre, nro_hogar
)
SELECT a.nombre AS aglomerado,
       ROUND(100.0 * SUM(CASE WHEN g.cantidad >= 3 THEN h.pondera ELSE 0 END)
             / SUM(h.pondera), 1) AS pct_tres_generaciones
FROM generaciones g
INNER JOIN hogares h     ON g.codusu = h.codusu AND g.anio = h.anio
                        AND g.trimestre = h.trimestre AND g.nro_hogar = h.nro_hogar
INNER JOIN viviendas v   ON h.codusu = v.codusu
INNER JOIN aglomerados a ON v.id_aglomerado = a.id
GROUP BY a.nombre
ORDER BY pct_tres_generaciones DESC
LIMIT 10;

6.7 Los atributos derivados, en una vista

En el modelo decidimos no guardar la cantidad de miembros ni el ingreso per cápita familiar. Una vista los calcula cada vez que se los necesita: es una consulta guardada con nombre, que después se usa como si fuera una tabla.

CREATE VIEW ingresos_hogares AS
SELECT h.codusu,
       h.anio,
       h.trimestre,
       h.nro_hogar,
       COUNT(*) AS miembros,
       h.ingreso_total_familiar,
       ROUND(h.ingreso_total_familiar / COUNT(*), 2) AS ingreso_per_capita,
       h.pondih
FROM hogares h
INNER JOIN personas p ON h.codusu = p.codusu AND h.anio = p.anio
                     AND h.trimestre = p.trimestre AND h.nro_hogar = p.nro_hogar
GROUP BY h.codusu, h.anio, h.trimestre, h.nro_hogar;

Un detalle que conecta con la normalización: la consulta agrupa solo por la clave primaria de hogares y, aun así, puede mostrar h.ingreso_total_familiar sin agregarlo. PostgreSQL acepta eso porque sabe que la clave primaria determina el resto de las columnas. Es una dependencia funcional, y el motor la usa.

SELECT *
FROM ingresos_hogares
LIMIT 5;

6.8 El ingreso per cápita, trimestre a trimestre

Para los ingresos del hogar INDEC indica usar PONDIH, el ponderador corregido por no respuesta. El promedio ponderado es la suma de cada valor por su peso, dividida la suma de los pesos:

SELECT anio,
       trimestre,
       ROUND(SUM(ingreso_per_capita * pondih) / SUM(pondih)) AS ipcf_promedio
FROM ingresos_hogares
WHERE trimestre = 1
GROUP BY anio, trimestre
ORDER BY anio;

Como el sitio se genera con R, el resultado de una consulta también se puede guardar en un data.frame y graficar. Abrí el código para ver cómo:

SELECT anio + (trimestre - 1) / 4.0 AS periodo,
       SUM(ingreso_per_capita * pondih) / SUM(pondih) AS ipcf_promedio
FROM ingresos_hogares
GROUP BY anio, trimestre

6.9 Una vista materializada

La vista anterior se recalcula cada vez que se consulta. Para un resumen que se mira seguido y cambia poco, conviene una vista materializada: se calcula una vez y el resultado queda guardado.

CREATE MATERIALIZED VIEW resumen_trimestral AS
SELECT r.nombre AS region,
       h.anio,
       h.trimestre,
       SUM(h.pondera) AS hogares,
       ROUND(100.0 * SUM(CASE WHEN h.id_tenencia = 3 THEN h.pondera ELSE 0 END)
             / SUM(h.pondera), 1) AS pct_inquilinos,
       ROUND(SUM(i.ingreso_per_capita * i.pondih) / SUM(i.pondih)) AS ipcf_promedio
FROM hogares h
INNER JOIN ingresos_hogares i ON h.codusu = i.codusu AND h.anio = i.anio
                             AND h.trimestre = i.trimestre AND h.nro_hogar = i.nro_hogar
INNER JOIN viviendas v   ON h.codusu = v.codusu
INNER JOIN aglomerados a ON v.id_aglomerado = a.id
INNER JOIN regiones r    ON a.id_region = r.id
GROUP BY r.nombre, h.anio, h.trimestre;

Consultarla es leer 198 filas ya calculadas, en lugar de recorrer más de un millón y medio:

SELECT region,
       hogares,
       pct_inquilinos,
       ipcf_promedio
FROM resumen_trimestral
WHERE anio = 2026 AND trimestre = 1
ORDER BY hogares DESC;
